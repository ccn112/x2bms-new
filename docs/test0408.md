## 2. TEST LUỒNG BQL ĐẨY PUSH XUỐNG CƯ DÂN  ⭐ (trọng tâm)

### Điều kiện cần (checklist hạ tầng FCM)
- [ ] `.env` server: `FCM_ENABLED=true` (đã có), `FIREBASE_CREDENTIALS` trỏ file service-account JSON **tồn tại** trên server (mặc định `storage/app/firebase/service-account.json`).
- [ ] Cư dân test đã **đăng nhập app bản prod** (`-t lib/main_prod.dart`) trên máy thật → app tự đăng ký device token (`POST /resident/device-tokens`) và **subscribe topic** theo tòa/dự án.
- [ ] (Kiểm token) Trên server: `php artisan tinker --execute="echo \App\Models\DeviceToken::count();"` > 0.

### 2A. Push TARGETED — BQL gửi tới 1 căn hộ (per-user, có sổ giao nhận)
1. Vào `/admin/notifications/center` → **Soạn thông báo**.
2. Loại: *Thông báo*; Tiêu đề tùy ý; **Phạm vi nhận = Căn hộ** → chọn căn **#2628** (hoặc #2629).
3. **Kênh gửi**: tick **“Đẩy về máy (Push)”** (và có thể thêm App/Email). → **Phát hành ngay**.
4. **Kỳ vọng:**
   - [ ] Máy cư dân (đã đăng nhập app) **nhận thông báo push** trong vài giây.
   - [ ] Mở app: thông báo vào **Hộp thư / Thông báo BQL**.
   - [ ] `/admin/notifications/delivery-audit`: có dòng **kênh Push · người nhận = cư dân · trạng thái “Đã gửi”**.
   - [ ] Nếu cư dân **tắt kênh** tương ứng trong app (Cài đặt thông báo) → dòng ghi **“Bỏ (tắt kênh)”** (suppressed), KHÔNG gửi. Kênh **Khẩn cấp** thì luôn nhận.

### 2B. Push BROADCAST — BQL gửi cả tòa (qua FCM topic, 1 message)
1. Soạn thông báo, **Phạm vi nhận = Tòa nhà** → chọn tòa **#6**; tick **Push** → Phát hành.
2. **Kỳ vọng:**
   - [ ] Mọi thiết bị đã subscribe topic `building_6` nhận push (1 message/topic, không nhân theo người).
   - [ ] Audit ghi **1 dòng topic-level** (`Topic: building_6`, người nhận = “— (broadcast topic)”).
   - [ ] Lưu ý: broadcast qua topic **không** lọc tùy chọn tắt-kênh per-người (đã chọn Push là gửi).

### 2C. Test push NGAY (không cần deploy code mới / không cần UI)
> Dùng khi muốn xác minh FCM thông suốt trước, bằng đường production của dispatcher.
```bash
php artisan db:seed --class=PushRoundDemoSeeder --force   # dựng TB demo mỗi kênh
php artisan push:demo-round                               # bắn 1 vòng (--only=announcement để chỉ 1 kênh)
# hoặc bắn thẳng tới 1 token cụ thể (bỏ qua FCM_ENABLED):
php artisan push:test --help
```
- [ ] Máy thật nhận push; `push:demo-round` in ra “→ N thiết bị”.
- [ ] Mỗi lượt bắn ghi vết vào `notification_delivery_logs` (đối soát ở màn audit).

**Nếu KHÔNG nhận push — lần theo thứ tự:**
1. `DeviceToken::count()` = 0 → cư dân chưa đăng nhập app prod (token chưa đăng ký).
2. File service-account thiếu/không đọc được → `PushService::enabled()` = false (mọi push no-op).
3. Targeted “no_active_token” trong audit → token chết; đăng nhập lại app.
4. Broadcast không nhận → thiết bị chưa subscribe topic (đăng nhập lại để re-subscribe).

## 4. TEST CỔNG CHỜ + CẤU HÌNH THAM SỐ THEO TÒA (Zalo/WhatsApp/Telegram/X.Space)

### 4A. Màn cấu hình
1. Vào `/admin/notifications/channel-settings`.
2. **Kỳ vọng:** thấy các dòng của tòa #6 — **Email: Đang hoạt động**; **Zalo/WhatsApp/Telegram/
   X.Space: Cổng chờ** (cột Tham số liệt kê key đã khai).
3. Bấm **Sửa** một dòng (vd Zalo): đổi tham số (oa_id/access_token…), Bật/Tắt, Trạng thái → **Lưu**.
   - [ ] Lưu xong bảng cập nhật đúng.
4. Bấm **“Khai báo kênh cho tòa”**: chọn tòa + kênh → form tự đổ gợi ý tham số theo kênh → Lưu.
   - [ ] Tạo được dòng mới (unique theo tòa×kênh; khai lại = cập nhật).

### 4B. Hành vi cổng chờ trong sổ gửi
1. Soạn thông báo **Phạm vi = Căn hộ #2628**, tick **Zalo** + **Telegram** → Phát hành.
2. Vào `/admin/notifications/delivery-audit`, lọc theo người nhận / kênh:
   - [ ] Kênh **đã khai tham số theo tòa** (Zalo/WhatsApp/Telegram/X.Space) → trạng thái **Chờ gửi**, lỗi **`provider_pending`** (đã cấu hình, chờ đấu nối provider — KHÔNG gửi thật).
   - [ ] Kênh **chưa khai** (vd SMS) → **`provider_not_configured`**.
   - [ ] Nếu **Tắt** kênh ở màn cấu hình → dòng ghi **`channel_disabled`** (suppressed).
> Đây là “cổng chờ”: hệ thống ghi nhận ý định + tham số theo tòa, sẵn sàng cắm provider thật
> (Zalo ZNS / WhatsApp Cloud / Telegram Bot / X.Space webhook) mà không phải sửa nơi gọi.
